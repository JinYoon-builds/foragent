An architecture decision record (ADR) usually describes a decision's consequences under three
headings. This is background only; it adds no step to the architect procedure.

## Easier

What becomes easier after the change, for example which edits stop overlapping, which lane can work
alone, which test gets faster or which state gets a single writer.

## Harder

What becomes harder or costs more, for example new indirection, a facade to keep, a migration of
open issues' Files or more modules to read. Most real changes have some cost here.

## Revisit

When the decision is worth looking at again, for example a number crossing a threshold, a planned
feature that changes an assumption, or a date.
