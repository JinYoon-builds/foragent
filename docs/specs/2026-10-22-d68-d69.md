# D68 first tidy (split runner.py) and D69 lane clones

Decisions: docs/decisions.md D68 addendum and D69 (commit 19038b8).

## Shared rules
- Code structure sets how much work can run at once: split `runner.py` first (D68 addendum).
- Split rule: `foragent.runner` keeps every old name importable, and patching `foragent.runner.<name>` still
  reaches the behaviour, because queued issues' locked acceptance tests use those names. Done = all existing
  tests still pass (D53 baseline + full test command) and behaviour unchanged; runner.py ≤ 500 lines, new
  modules ≤ 600.
- Plans may list `files` per issue (expected files to change). Missing files = unknown = never cloned.
- The gate adds a second worker to a lane (max 2 per lane) only when: 2+ issues wait in the lane, capacity
  is left, the candidate's files do not overlap any running issue's files in that lane (globs count), and the
  candidate has no open blocker. Wrong guesses fall back to normal conflict handling (rebuild on latest main).
- The view shows a cloned lane as `orch ×2`.
