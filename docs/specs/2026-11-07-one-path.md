# One path to main (2026-11-07, Jin q57 A and q58 A)

## Problem
Architect r985 measured the publish -> main path on 11-07. Main has several writers: flush pushes orders directly while the merge owner lands trains, memory and publications. A flush holds the journal and publication locks across a merge-train wait of up to 40 minutes, so preparation claims time out, and the owner refuses publications during any train. Publications took 229-769 minutes. PM r982: test preparation cannot open a terminal. PM r984: 63% of issue-minutes are 'unknown', mostly owner-queue waits and lost early flow records. Architect r986: the worker-side merge path runs only with merge_owner off and doubles every merge-path fix.

## Decisions (Jin, 2026-11-07 11:20 KST)
- q57 A: scenario locked tests first, then three steps: flush only enqueues; neutral writes land during a train; one commit per owner pass. Include r982 and r984.
- q58 A: a new decision makes the merge owner and batch merge the product default; retire the old path's locked files; delete the old path after the scenario tests are green.
- Implementation starts after the in-flight bundles merge (#2444, the orch-owns order, the merge-owner bug order); tests are prepared now.

## Targets
Publication-to-lane p90 under 15 minutes while a train runs; lock-timeout events 0 per 24 h; main moves per 24 h from 163 to about 110; red re-runs per publication 1.

## Out of scope
Direct single-PR merge priority command (idea retained). Train member selection. CI configuration.
