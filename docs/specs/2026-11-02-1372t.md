# #1372: gate-owned PR composition

Every pull request body Foragent sends, on creation and every body update, stays within GitHub's 65,536-character limit. This includes implementation publication and refresh, native review publication, review-only publication and merge retitling, batch publication, harness-held publication, dream publication, and temporary group-check PRs. A completed run must not lose its PR to a body-length error, and no attempted create or update may send an oversized body.

No code parses a rendered PR body to decide what is required. Compose the body from structured values: the actual issue closing reference (or non-closing batch parent reference), short change summary, review verdicts, approval lines, machine markers and marker pairs, human-check items, and optional blocks. An update composes again from the same recorded values, with explicitly refreshed review/risk/lane facts; it does not read, patch, classify, or copy the old body. This includes merge-retitle callbacks in the run and orchestrator paths. Remove with_review_scope, risks.refresh_notes, and refresh_lane_decisions and migrate their callers; do not leave unused body-patching APIs behind. Remove all TRY.md-heading extraction for required summary selection. TRY.md may be carried as one opaque optional block. Display-only try-card and inbox readers may still render the gate's published projection; their parsed output never becomes a publication or approval input.

D95 ownership: the gate is the sole owner of the PR body and its persisted composition values. The agent supplies the summary as a structured value (.foragent/PR.json, JSON object with a string summary); the gate ingests it and writes the durable pr-content/<issue>.json record before publication. Preserve the complete rendering inputs there, not a finished body to parse later: check rows/results, attempt metadata, review verdicts/findings/notes, summary, raw try instructions, rebuttals, searched evidence, and any non-derivable display metadata. Closing references come from the issue identity, human-check items and approval attribution from the approved issue snapshot/Approval record, and current risk notes, lane decisions and scope from their existing records/configuration. Persist missing values before cleanup; record any other non-derivable value or drop it explicitly. A legacy PR with no summary/values record stops and reports the missing record before a body write; it must not backfill from the old PR body or TRY.md headings. Keep the new summary artifact across worktree recreation. Internal helper names and representation beyond these producer/record inputs belong to the implementer.

A person's edit to a PR body is overwritten by a gate body update. People communicate through issue and PR comments. No preservation of human body edits, custom scope paragraphs, or edited PR checkboxes is required, and no edit-overwrite notice is required. Issue approvals, merge approvals, verdict judgment and their existing requirements do not change; an inbox display of unchecked PR boxes is not approval authority. Never reconstruct approval facts from a rendered PR body.

Use one composition budget. Required content stays whole: the correct Closes #N on issue PRs, non-closing batch parent reference, short summary, review verdict and approval lines where present, human-check items, the gate's machine markers, and complete start/end markers of every present pair (including risk-notes and lane-decisions). The text inside a pair is optional. Give each optional block (risk notes, lane decisions, quotes, check/child tables, findings, try instructions, rebuttals, evidence) an independent equal share of the remaining character budget, including framing and omission notes. When the complete composed body fits, return it unchanged, including exactly 65,536 characters and multibyte text; do not repartition an already fitting body. A block over its share is replaced in full by one short note naming what was removed and where the complete text is retained in this PR's comments. No block's length can remove another block or a required value. Comment chunks must retain the complete original text after worktree cleanup. A named PR-comment reference (rather than an ID learned only after creation) is sufficient, so initial publication requires one create call, and an ordinary refresh one update call, with no length-error retry or body rewrite just to insert comment IDs. Publish the named comments as part of that operation; report any retention failure and retain the source values for recovery.

If required content alone exceeds 65,536 characters, stop before writing any PR body and report the required size and limit without cutting required content. Account for omission-note/framing overhead too: if a faithful bounded composition cannot fit, stop and report rather than send an oversized body. Batch PRs keep the parent reference without a closing keyword and retain existing completion semantics.

Implement from current main, not PR #1565 or the earlier held shortening branches. Replace the old string-shortening contract and its conflicting test fixtures through the supplied locked content, preserving all existing node IDs and required-content checks. Retire the old parsers and their body-preserving unit-test expectations rather than add a new classifier. No keyword/regex meaning judgments, model decisions in scripts, or case-specific shortening exceptions are part of this change.
