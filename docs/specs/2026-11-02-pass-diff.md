# Keep reviews after PASS within this PR

## Decision and evidence
Jin decided option A on 2026-11-02. The supplied incident is #1644 round 8: after PASS, integrating main changed the head; a later review blocked on config.py from merged #1638. This incident is supplied context, not a live GitHub measurement.

The supplied main is 8afa8a7b02d12842b5253a12c2186ec996dbd6f1. Its ordinary post-PASS review compares the accepted head directly with the staged tree and explicitly tells reviewers that main's imported changes can block. The normal PR comparison already has a merge-base boundary. The reviewer lacks the right provenance in its input, and its instruction explicitly permits reviewing another issue's work. Fix that boundary and instruction; the reviewing agent continues to judge findings. Do not add a semantic classifier, finding filter or required agent search sequence.

## Required result
After a reviewer PASS on the same approved issue body, a later review caused by a changed head receives only this PR's changes against current main, using their merge base. Code that arrived solely by integrating main is absent from review input, even when main edited a separate part of a PR file. Its own issue already reviewed it. Lines changed by conflict resolution and new own commits remain reviewable and can block. The earlier PASS still protects unchanged accepted code; retain its exact head and review record and durable nonblocking NOTE behavior. CI still checks whether the combined code works; change no CI rule.

Replace #1599's obsolete main-integration expectation in tests/acceptance/test_review_pass_scope.py::test_main_integration_after_pass_counts_as_changed_code through this order's acceptance_files, keeping its name and all merge/rebase and upstream/changed node IDs. Reason: it explicitly requires the main-only changes that Jin now excludes. Its shared assertion also encodes the old same-file main delta; revise only that provenance expectation so the real conflict test uses the new rule. Preserve every other test node and its PASS/body/risk/setting guarantees. Related unlocked unit tests have obsolete main-delta/exemption expectations too: migrate those expectations without dropping nodes. A main-only file does not acquire PR scope merely because its risk entry is marked; marked entries matching this PR's changes still keep full scope.

Append a dated 2026-11-02 entry to docs/decisions.md using its existing format. Explicitly supersede #1599's phrase "including code integrated from main" with this decision and its reason; retain historical entries. Keep #1599's remaining behavior: same body keeps its PASS, a body edit restores full review, matching exempt risk entries retain full scope, and review_pass_scope keeps its current default and off behavior. No new durable state or writer is needed; existing review/publication records retain their current owners.
