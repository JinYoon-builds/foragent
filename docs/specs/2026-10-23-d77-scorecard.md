# D77: the orchestrator reads its own scorecard

See docs/decisions.md D77. Programs compute numbers from local records only (no GitHub calls, D67); the orchestrator judges, finds root causes and files fix issues. Speed rises only by removing waste; weakening checks (locked tests, cross review, merge conditions) is a trade-off for the person (D71).

Pieces:
1. scorecard-records: count every `gh` call in a local per-UTC-hour counter (`StateStore.github_calls()`), and journal each review verdict as a `kind=review` event in orch-events.jsonl the moment it is known.
2. orch-scorecard: `fa orch scorecard [--json] [--days N]` (default 7). `today` = last 24 hours; `previous` = per-day median over the N-1 days before. Metrics: runs, merge_rate, median_minutes_to_merge (run start to merge), github_calls_per_hour, review_returns, reverts_after_merge (main commits that revert a merged run's commit). `worse` lists metrics worse than previous; `repeated_failures` groups today's non-merged runs by identical reason (count >= 2); `unexplained_failures` lists today's non-merged runs with no reason. Human output: one line per worse metric, or a no-change line.
3. scorecard-skill: skills/fa-orchestrator/SKILL.md runs the scorecard every cycle and states the rules above; the reviewer prompt gains a checklist item for tests that assert nothing.
4. fa-briefing-scorecard: `fa brief` (the /fa briefing, #119) shows one line for the worst metric, before -> now, e.g. "Slower than usual (10 min -> 36 min)", and nothing when no metric is worse.

Deferred: tidy debt (D68) joins the scorecard after `fa tidy due` (#157) merges; "main broken after merge" needs main's CI result recorded locally and is a later issue.
