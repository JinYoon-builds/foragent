# The reviewer gets a per-project risk map (D84)

Evidence (2026-10-24): the planning session found two gaps in #261's implementation only because it knew that morning's kill incident; the gate's cross reviewer reviews all code with the same strength and no history. An empty acceptance baseline once let merges through unprotected.

- `.foragent-risks.yml` at the repo root: entries with paths, why (incident date and summary), review guidance, optional always_human, optional fixed_by and guard_tests, and an added trace (by, at, event). Missing file: reviews unchanged.
- A PR touching a mapped path: the reviewer prompt includes the matching entries, states that unmapped code still gets the full review, and the review runs at the l tier regardless of issue size; always_human holds for a person like config always_human.
- `fa risk add` appends with trace and keeps the file byte-for-byte; `fa risk list --json`; `fa risk candidates --json` lists dangerous-pattern code (signals, rmtree/rm -rf, git push/merge, GitHub writes, policy/baseline/approval checks), marks coverage and proposes entries without writing the map.
- Seeds: process-termination code (2026-10-24 kill incident) and baseline/merge policy (empty baseline merged unprotected), each with guard tests.
- Product ships the mechanism; contents are per project. Measuring misses (incidents outside mapped paths) goes to `fa orch facts` (#333) later.
