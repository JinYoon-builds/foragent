# CI mode: the acceptance comparison runs in GitHub Actions

Evidence (2026-10-25): every run captures and compares the acceptance baseline on this machine (465+ tests, 8-14 minutes under load); this is the main limit on merges per hour (Jin's target: 5/hour). Jin decided (~10:50): add a per-project choice; local stays the default; the Foragent repository itself switches to ci once this lands.

- `.foragent.yml` `checks: local | ci` (default local, unchanged behaviour).
- `fa init` recommends ci for public repositories and local for private ones (Actions minutes cost money) and lets the person choose.
- In ci mode the comparison (passing set before vs after, excluding locked tests of open issues) runs sharded in GitHub Actions; the runner reads every shard's result from `foragent-acceptance/{index}` check runs and applies today's rule; tests marked `local_only` (macOS launchd, real executors, terminal opener) still run on the machine.
- No merge without a usable comparison in either mode (#327); a missing, partial or unparseable result never merges; a CI that never started holds as infrastructure (#368) or falls back to local when `checks_fallback: local`.
- Facts record where each comparison ran and how long it took.
