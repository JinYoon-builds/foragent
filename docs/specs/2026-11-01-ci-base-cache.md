# S1 ci-base-cache: trusted per-node reuse

In checks: ci, a trusted base-branch push records the completed base result of every individual portable test node in the full selection WITHOUT exclusions for other open issues. Reusable identity binds repository/base SHA, test node ID and the trusted base acceptance directory, normalized test command and marker. Open-issue exclusion lists and PR shard index/count do not invalidate otherwise matching per-node results. Producer execution may partition or parallelize measurement internally, but reusable coverage is addressable by node ID across all PR shards. For its current base-side selection, each PR shard reuses every covered node and executes on base ONLY the selected nodes the trusted record lacks (partial miss). A completely absent, stale, mismatched, unreadable or corrupt record is a miss for the selected nodes and falls back to current base execution. Non-exclusion selection inputs still bind the record; missing node entries are partial availability, not evidence that those tests failed. Apply the PR's current exclusions to the comparison exactly as today: excluded cached results never acquire protection or affect the verdict, and excluded nodes do not leak into the comparison report. Continue to measure the exact head and preserve the same passing-set loss/regression verdict as an uncached run, including a base-passing test that failed or disappeared on head. A PR never publishes or repairs reusable records, even after a partial miss. Only trusted base-branch push runs may publish or refresh them. The generated workflow must make this trusted full node coverage available to every PR shard independently of changing open issues and shard assignments; the committed acceptance workflow must exactly equal fa ci workflow output.

Current cause: src/foragent/ci_shard.py main() unconditionally measures base and head, while the previous draft incorrectly used a PR-specific exclusions/shard snapshot as reusable identity. Exclusions change as other issues open or close, so that identity would turn ordinary later PRs into cold misses. src/foragent/ci_pytest.py currently filters collected items by shard and records collected/passing IDs; selection/measurement must support observing and executing only genuinely uncovered base nodes. The final comparison in foragent.ci_mode.comparison already uses passing-set subtraction and rejects reports containing excluded IDs; preserve that policy. Trusted base configuration, shard-layout validation for PR comparisons, measurement completeness, exact revisions and tracked-tree integrity remain authoritative. No person decision is needed (architect r201 / orchestrator S1).

The reusable dataset covers the full unexcluded portable base selection, including known failing tests. PR-specific exclusions and shard layout are projection inputs, not freshness. The PR still reports its exact current exclusions and selected collected/passing IDs to the unchanged comparator. Head deselection of a previously passing base test remains a regression.

The public snapshot input is FA_BASE_CACHE_FILE. Trusted push mode is FA_BASE_CACHE_MODE=produce; it has no open-issue-exclusions input. A JSON results object maps node IDs to their producer-recorded outcomes; scope exposes acceptance_dir, command and marker. Other fields and node-value encoding remain implementation choices. The partial-availability fake removes exactly one genuine results entry while preserving trusted producer metadata and every other result. This is not a synthetic passing/failing verdict or authorization from a record header. The transport still has to establish trusted origin.

Producer coverage may be measured in parallel and aggregated behind the public entry. PR cache lookup reaches the full node pool regardless of its current shard. All PR cache access is restore-only: neither full nor partial misses publish or repair records. Invalid whole records fall back as before; a valid pool missing a node requires only that selected node to run on base. Keep non-exclusion selection validation and complete/revision/tree checks.

Acceptance observes actual node execution through tiny real pytest bodies, public ci_shard.main(), public ci_mode.comparison(), and fa ci workflow. It covers differing exclusion lists with passing/regression parity; one missing node, including one of two tests in a shared file; excluded cached passes; different PR shard assignments; and retained trust, stale/corrupt, workflow and local protection contracts.

All three acceptance files belong to this one issue. The full replacement of test_ci_mode.py changes only its PR-workflow assertion, as in the prior corrected draft. There are no external or later-plan dependencies.

Trust and visibility: GitHub Actions caches written in a pull request are visible only to that pull request, and a pull request controls its own run. So a reusable base record must be produced by a run on the base branch itself (for example on push to the base branch after each merge), and a PR run must never accept a base record written from a pull-request scope, its own or another's; in that case it is a miss and the base runs as today. Without a base-branch record there is no speed gain, so the base-branch production is part of Done, not optional.
