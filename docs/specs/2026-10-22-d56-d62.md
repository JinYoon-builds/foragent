# D56–D62: skills by link, one entry point, push to the limit, one voice, a finished lane view

Decisions: docs/decisions.md D56 addendum, D57 addenda 2–3, D58 (with addenda 1–2), D59 (with its
addendum and the gate-merge reinstall gap), D60, D61, D62, and the D41 color addendum.
The acceptance tests under `tests/acceptance/` are the contract; this page holds the shared rules.

## Shared rules
- **People never get a command to type** (D57). Foragent runs it. Guidance text names only `/fa`.
- **Facts in code, judgement in agents** (CLAUDE.md root-cause rule). Code collects facts (usage,
  machine load, catalog, inbox), validates shapes, and enforces safety lines (style skills: one per
  lane; Claude keep-share cap). Choosing skills, summarising, and recommending what to do next stay
  with agents.
- **Voice** (D61): `docs/voice.md` is the one-page standard for every word Foragent shows people:
  skills, briefing, TUI, notifications, issue and PR text. Korean: 해요체, no excessive honorifics.
  English: conversational, contractions allowed. Both: active, positive, no noun stacking, short
  sentences, one idea each. Toss UX writing principles + ASD-STE100; no Toss branding.

## Skills (D56 addendum, D58 addendum 1–2)
- Libraries download themselves when missing (`catalog`, `install`, `init`).
- `fa skills add <git url>` is an agent tool: preview (`--json`) changes nothing; `--approve`
  registers the library in the global config and records `skill_roles` (style | review | tool |
  domain) the person confirmed. Tool copies (`.claude/`, `.codex/`, `.cursor/` …) of one skill
  show as one skill everywhere. `runs_scripts` is a fact: the skill dir holds script files.
- Lane `skills` in `.foragent.yml` now means **fixed skills a person chose** (style skills).
  `fa lanes skills <lane> [ids]` sets them; at most one `style` skill per lane.
- Every other approved skill is offered to the lane agent per issue ("Available skills" with paths);
  the agent reports `Skills used: …`, which goes to run state and the PR body.
- D58 addendum 3 (global skills leaking into `claude -p`) stays open and out of this order.

## `/fa` and the briefing (D59)
- `fa brief [--json]` gathers facts: working, queued, to see, team (with `no-skills` warnings),
  profile, usage. `/fa` shows the briefing, confirms the profile once per session, then routes to
  init, inspect or order. Existing skills stay callable; guidance names `/fa` only.
- Project profile (kind, stage, priority, confirmed_at) lives in `.foragent.yml` `profile`, written
  with `fa profile set`. The interview engine default is `native`.
- The gate's own fast-mode merge reinstalls Foragent like `fa orch merge` does.

## Push to the limit (D60)
- Concurrency: AIMD on machine headroom (`next_parallel`, `machine_load`). Ceiling = lanes with
  work; `max_parallel` becomes an optional hard ceiling (default none). Increase step spacing is an
  implementation choice; start with one increase per completed tick interval of at least 2 minutes
  and record the choice in the PR.
- Usage: read Claude `rate_limit_event.rate_limit_info.unifiedWindows` and Codex `rate_limits`
  into `StateStore.usage()`. On a limit, pause that executor until the window resets; unreadable
  usage falls back to `limit_wait_minutes`.
- Claude quota mode `keep` (default, cap at `keep_percent` 80) or `burn`; local override via
  `fa quota mode`, `m` key in the lane view, `fa init --claude-quota`. Codex always burns.

## Lane view (D62, D41 colors, D57 addenda 2–3)
- Finished order: "이번 주문을 모두 끝냈어요 ✓" plus merged issues. No empty frames, no repeated
  counts, symbols carry words, nothing overflows the width.
- Orchestrator events show the agent's `--say` line; raw summaries stay in the log.
- Bottom status line: usage + age, reset, memory, concurrency, mode. Idle with quota left says so.
- Colors follow the terminal theme (default background), no yellow.
- Split side by side: Orca vertical, tmux, iTerm2, WezTerm, Kitty; Apple Terminal opens a window.
