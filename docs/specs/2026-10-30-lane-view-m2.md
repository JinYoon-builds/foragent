## Root causes and existing seams

1. watch_art.ansi_rows serializes half_blocks' bottom-only ("▀", None, lower) cell with background alone. The visible upper half inherits the terminal's light default foreground. Correct ANSI serialization, while retaining the half_blocks data contract, fixes every ansi_rows consumer rather than masking a squirrel outline.
2. The current screen is built around text rows per worker, an issue box which replaces the rows, old order-child progress, and separate panels. Those representations cannot express the approved one-squirrel-per-lane blocks and persistent explanation bubble. watch_layout already discovers watch_sections modules by ORDER; i18n already discovers messages modules. Reuse these seams and the watch facade's existing public APIs rather than copying the prototype loop or building a second UI framework.
3. watch_terminal erases on every iteration, advances animation by 0.3 seconds, and schedules reads separately. Preserve asynchronous reads, keyboard/settings behaviour, view ownership and reload cleanup, while painting in place, animating at about 0.5-second intervals and reading data every 5 seconds. Correctly erase remnants of shorter content without clearing the screen every frame.
4. The role caller only persists full why. The prototype tries to turn it into display copy by splitting punctuation. What the agent lacks is a separate tool input and durable field for the human explanation, plus caller guidance to write it in the configured language. Give it --short and persist it alongside why. The agent chooses the words; scripts do not summarise, translate or infer meaning.
5. Recorded waiting/phase/claim, parked, weekly results and newest lane memory facts live in local records, approval Files, journal events and configuration; per-issue run-hours/github/memory holds have no durable writer and stay unknown. Expose/read those facts. Read recorded overlap/capacity facts and park/unpark semantics; do not guess a cause from issue prose or call GitHub during rendering.

6. Round 1 asked implementers to match lane_live.py, but that file exists only in the scratch folder and is not published with the issues. Reference prototype below supplies exact pixel grids, colour/span data and bilingual copy in the shared spec itself; implementers no longer need inaccessible context.
7. The locked main palette test rejects the real yellow required by the approved view. Shell changes base pair 2 and its attached copy changes only that assertion in the same issue, keeps every function name and all other guards, and explicitly documents the superseding requirement; skeleton's fixed ANSI8 lookup removes the remaining colour ambiguity. Skeleton preserves main's base pair 2 until shell, registering the new working style separately.

### Sideways acorn spans

The exact visible shape is `◖█#N word▌`, with no internal padding, no space between stem and cap, and one space between #N and a nonempty word; with word='' it is `◖█#N▌`. Two spaces separate complete acorns. The prototype's `acorn(text, colour, ink)` emits these four spans in order (each reset in ANSI transport): stem, cap, bold text body, half-cell edge. The stem and cap have the same cap foreground on the terminal default background; the stem never uses the body colour. The structured Line transport carries the same foreground/background values without ANSI escapes. Body spans retain bold when converted to curses attributes (the painter adds A_BOLD to structured art spans with a painted background); this supplements style_attribute's colour callback without changing its signature or tuple shape.

| style | stem at ticks 0,1,2,3 | stem and cap fg | body fg / bg | body text | edge fg / bg |
| --- | --- | --- | --- | --- | --- |
| working (legacy yellow alias) | ◖, ◜, ◖, ◟ | 94 / default | 232 / 220, bold | #N step | 220 / default |
| question | ◖, ◖, ◖, ◖ | 94 / default | 232 / 203, bold | #N 질문 / #N question | 203 / default |
| next | ◖, ◖, ◖, ◖ | 237 / default | 252 / 240, bold | #N | 240 / default |
| parked (product addition; no prototype parked style) | ◖, ◖, ◖, ◖ | 237 / default | 252 / 240, bold | #N 보류 / #N parked | 240 / default |

Equivalently a working acorn is `[(stem, ('art',94,None)), ('█', ('art',94,None)), ('#N word', ('art',232,220)), ('▌', ('art',220,None))]`. Substitute the table colours for other states. ASCII is one named-style span `[#N word]` (or `[#N]`), ignores tick, and has no rocking stem. Canonicalize both paths first: yellow -> working, parked -> next, unknown -> next; preserve working/question/next and the caller's literal word. All non-working stems stay ◖. Unknown style values use next colours and a fixed stem (and named 'next' in ASCII); never imply that unknown work is running. Parked uses the next colour scheme with its own word. The prototype only defines NOW=220, HAND=203, NEXT=240 acorns; these last two fallbacks are explicit additions. Palette D is unrelated to acorn colours.

Other prototype colours are DIM=244, INK=254, DONE=137, OK=114, LINE=238; its heavy lane rule is 242, waiting sentence 147, unfilled progress bar 237. The existing named styles/pairs in Contracts continue to apply, including the explicit next/separator 8-colour dim attributes.
