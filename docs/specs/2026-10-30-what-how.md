# Planning decides WHAT; the lane owns HOW (D98)

## Why

Jin, 2026-10-30: "이게 근본적인 문제였구나. 일단 그렇게 바꾸는게 맞는듯."
Planning sessions and the orchestrator have been choosing function names, payload shapes
and copy before the lane sees the work. Locked tests sometimes call internal helpers.
Preread then asks the implementer to list every guess, and any non-NONE line blocks approval.
The supplied incident records 82/44/24 and 111 preread unknowns and about three hours waiting
for plans. These numbers are incident evidence, not new thresholds.

The supplied main snapshot confirms the mechanism:
- src/foragent/order.py: preread_prompt asks for every unknown; _unknowns puts every
  non-NONE response line in unknowns; require_clean_preread blocks when that list is nonempty.
- skills/fa-order/SKILL.md: steps 2, 3 and 6 settle reversible details in planning and repeat
  preread until every issue has no unknowns. That removes the lane's authority over HOW.
- src/foragent/run_implementation.py builds the implementation prompt; src/foragent/run_prompts.py
  supplies its text and the reviewer instructions. Preread currently records no proposal to
  carry into the implementation or review context.

The missing inputs are an instruction granting the lane authority over HOW and a durable
handoff of its proposal. Fix those boundaries and that handoff. Do not decide the meaning of
prose with keyword lists, similarity rules, case-specific branches or LLM calls in scripts.
The lane classifies its own response using the explicit APPROACH, DECIDE and QUESTION protocol.

## Decision: D98, 2026-10-30

Issue 1 appends a Korean D98 entry to docs/decisions.md, using that file's format and date.
Planning and the person decide WHAT: goal, scope, behaviour a person notices and contracts
between issues. The lane owns HOW: structure, names, values and internal shapes, and records
its choices. Preread is the lane's design proposal. Review judges tests, goal, principles and
real defects, rather than taste. Structural observations use NOTE and never fail a review.

D98 replaces the fa-order step-6 "never answer an unknown yourself / until every issue has
no unknowns" rule and the relevant top-down HOW prescriptions of the 10-27 skill plan.
Identify those superseded rules in the new entry. Keep the existing principle skills and
independent locked-test verification. Earlier decisions' zero-unknown wording now refers
to unresolved WHAT questions, not reversible lane choices.

Locked tests exercise observable behaviour at CLI, HTTP, rendered-screen or file boundaries,
or through public functions the issue explicitly names as its contract. They do not import
internal helpers unless that function is explicitly declared as the issue's contract.
A shared interface is a WHAT contract between issues; private choices within one issue are HOW.

## Contracts

- Preread remains read-only and uses the configured lane implementer. Its requested response is:
  "Your lane owns HOW. Reply with: a short APPROACH (<= 8 lines); DECIDE: <choice> lines for
  reversible details you will settle; QUESTION: <q> lines only when the WHAT is ambiguous:
  a wrong guess would fail a locked test, break a contract with another issue, or change
  behaviour the person notices. Reply NONE if nothing to add."
  Retain the old prompt's unknown terminology and exactly-NONE instruction for the empty
  response, as required by the unchanged locked preread prompt checks.
- QUESTION lines and legacy plain lines are unknowns. APPROACH and DECIDE entries are retained
  with the preread evidence and never block approval. Empty/NONE replies remain supported.
  Scripts parse the explicit response protocol; they do not judge which choices count as WHAT.
- fa order preread --json exposes unknowns, decisions and approach for structured responses.
  Compatibility assumption: a response containing only legacy plain lines or NONE retains
  its existing exact key/unknowns JSON shape, omitting empty new metadata. This reconciles
  the new fields with tests/acceptance/test_order_preread.py's exact payload assertions.
  No existing locked file is edited to permit the change. Metadata representation inside
  the stored record is the lane's choice.
- The existing preread writer remains the sole writer of preread evidence. The implementation
  and review paths consume the evidence associated with the issue's approved current content.
  Replaced proposals, another issue's evidence and evidence invalidated by plan changes
  must not be substituted. Keep the existing content-bound approval and missing/stale-result gates.
  Do not add an independently authoritative copy of preread state.
- Starting the issue through public foragent.runner.run_issue delivers the approved proposal
  to the real implementer as "Your lane's earlier plan". The lane chooses the storage and
  transport details. Tests inspect the executor's input, rather than internal prompt plumbing.
- Issue 3 consumes issue 1's recorded DECIDE context. It may extend the handoff while preserving
  that contract. Its explicitly named public prompt contract is
  foragent.run_prompts.build_review_prompt; actual reviewer invocation is also checked through
  public run_issue. No new parameter names or private record shapes are prescribed here.
