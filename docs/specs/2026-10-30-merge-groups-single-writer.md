# #459/#460 single-writer merge groups (r17)

The root cause of the paused #459 design is duplicated ownership: the leader was instructed to merge, close, update records and sync boards for live member runners. The old tests hid that ownership violation by projecting leader merge events onto PR owners and waiving their later empty lock holds. #460 also instructed the leader to remove culprit queue entries. Replace that model with r17's append-only claim/verdict evidence over the already merged #712 FIFO log. Each member consumes evidence and completes itself on its own turn.

These are edits to existing issues, not new issues, and do not implement or publish the feature. Existing names in both locked modules are retained, including historical names whose r17-equivalent body now tests self-publication. #459 retains its configuration, combined checks, policy exclusions, final short-lock checks, singleton fallback and merge facts. #460 retains halving, pinned-base checks, culprit-owned retries, cached exact-set outcomes, interaction fallback and diagnostic accounting.

Interpretations: the old JSON queue, queue deletion, recursive lock-race harness, peer completion and ci-mode queue bypass are superseded by #712/r17. ci mode still does not form groups. A bisect verdict persists bisect_checks and may name fallback members; those fields supply evidence for owners rather than letting a leader write their records. No new message is hardcoded: new human text uses the English/Korean messages registry.

Locked-test review: tests/acceptance/test_merge_turn.py contains a pre-group tracker that requires each expected PR head to descend from current main and asserts that every successor logs re-verification. Exact-head group reuse can conflict with those expectations when that test forms a multi-member group. This order leaves that unrelated locked file unchanged and reports the conflict for the order owner; it must not be worked around by fake logging or by head rebases that invalidate the verdict.
