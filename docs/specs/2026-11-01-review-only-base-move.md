# D: review-only runs follow a moving base

## Outcome

A valid waiting PR can finish through fa orch resolve N --verdict pass or fa orch rerun-review N when its head is behind the current target base. A clean base merge updates the existing PR head, the updated head's Done when checks run exactly once for that move, its CI and ordinary FIFO merge policy still apply, and the existing PR merges without a RISK_HIGH retry-implementation flag or an implementation round. Further base moves receive the same treatment. A head that already contains the base keeps today's behavior: one verification, the same head, and no refresh push.

Resolve's recorded pass belongs to the exact head it judged and replaces that head's reviewer round. It can carry forward through a clean base merge whose result contains only the reviewed work plus the base changes, just as the existing publication path does after review. It cannot authorize an independently changed head or additional edits. Resolve performs no reviewer round for that clean update. Rerun-review reviews the existing head once, then a clean base update needs checks but no additional reviewer round. Failed updated-head checks or commands that change its tracked contents still prevent publication and merge; resolve retains its existing evidence-backed retry behavior.

A real merge conflict stops without a silent merge, implementation turn or invented resolution. Match this checkout's existing reviewed-head merge-turn conflict contract: base-changed, RISK_HIGH, the PR stays open and the remote head stays unchanged. That flag is allowed for a real conflict because the existing path emits it; ancestry alone is not a conflict. Preserve all existing refusals for an unexpected PR base branch, a changed head versus the verdict head, missing/invalid approval, approval/body/acceptance hash mismatch and missing machine checks. Preserve ordinary merge policy, CI and final head/base checks.

## Cause and existing rule

src/foragent/run_review.py::_review_only currently refuses immediately when the current base SHA is not an ancestor of the waiting PR head, with RISK_HIGH and “retry implementation on the current base.” Main advances on every merge, so this condition describes ordinary waiting PRs. It is not evidence that the reviewed work must be implemented again. The supplied 2026-11-01 observation says all sampled waiting heads were behind main; this draft does not claim a new live sample.

This checkout already has the intended distinction. The implementation publication path in src/foragent/run_publish_flow.py merges a moved base after review and verifies result-affecting changes without repeating the reviewer round. src/foragent/run_publish_reviewed.py::_publish_reviewed_in_turn likewise has a reverify callback: on its merge turn it cleanly merges a moved base, verifies the new head, lease-pushes it and rechecks its CI. It preserves the existing verdict across that clean Git base merge. On conflict it quits the merge and returns base-changed with RISK_HIGH. Its refresh currently notices a different target SHA from the captured base; a head already behind that captured base is rejected earlier and never reaches this capability. The defect is inconsistent base freshness handling at review-only entry and publication, not missing review authority or a need for scripted semantic judgment.
