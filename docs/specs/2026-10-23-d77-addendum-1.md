# D77 addendum 1: the break-it rule and review notes

See docs/decisions.md D77 addendum 1.
- Break-it rule, used verbatim: "Make the code return a wrong value, skip an effect, or do the effect twice. If the test still passes, it proves nothing." (pstack principle-test-behavior-not-implementation, MIT). It judges acceptance tests written by /fa-order (step 5), tests implementers write or fix (implementer prompt), and the reviewer's "test that proves nothing" item (#226).
- Review strictness A: the only new rejection reason is a test that proves nothing. Root-cause and structure findings are not rejections: the reviewer writes them as `NOTE:` lines, and the runner records each as a `review-note` event for the D77 scorecard and the D68 tidy cycle.
- B (the whole pstack interrogate rubric as rejection reasons) comes later, after the plumbing fixes and the #225 scorecard.
