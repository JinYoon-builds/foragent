# D80 stage 1: a plan file with lane pauses and expiry

See docs/decisions.md D80. The orchestrator judges; the gate executes. On 2026-10-23 ordering was faked with blocked_by links (30 orch issues waited 8 hours behind #138), lanes were paused by calling a Python function with no record, and parallelism was set by hand in config.

- One per-repository `plan.json` in the state folder holds the lane queues (#235), paused lanes (`until`, `why`), `expires_at` and `written_by`. `fa orch plan --json` prints it; `fa orch plan --expires <ISO>` sets the expiry.
- `fa orch pause <lane> --until <ISO> --why <text>` (why required) and `fa orch resume <lane>`; a tick starts nothing in a paused lane until resume or `until` passes. Each call records an event (`plan-pause` / `plan-resume`) with who, lane, until and why.
- An expired plan is ignored: ticks fall back to defaults (lowest number first, no pauses) and record one `plan-expired` event.
- Safety lines win over the plan: real blocked_by and pauses are never overridden by a queue.
- Entries written by a person are not overwritten by `--by orchestrator`; the call exits non-zero and says a human wrote it.
- Stage 2 (per-issue assignment, goal tool, review loop in the skill) comes after measuring stage 1 on the D77 scorecard.
