- [id:1231-2026-10-31-dream-redo] A dream redo is derived, not stored: `fa orch dream --redo <lane>` closes only `foragent/dream-<lane>` and appends a `dream-redo` event; `dream_due` treats the lane as due while that event follows its last `dream-done`, and `awaiting_pr` must filter to DONE/PUBLISHED so a redo never hides a published PR. The command starts no worker; it kicks the tick so admission stays in `orch_dream.start`.
- [id:1231-2026-10-31-redo-answer-by-time] A redo is answered only by a dream whose `covered_until` (the time its prompt was built) is later than the redo, not by journal order: the tick's reconciliation of an old merged dream PR, or an old worker finishing, appends `dream-done` after the redo but must leave the lane due. Stamp redo events with `store._now()` so they compare on the same clock as `record_done`.
- [id:1231-2026-10-31-redo-tick-closes] A redo command must not close the stale dream PR itself: a worker of unknown liveness can publish after the lookup. Keep the command journal-only and let `orch_dream.start` be the single closer via `stale_for_redo` (no publication, or `covered_until` <= redo time); `fa orch merge` refuses the same PRs.
