- 레인 기억은 두 작성자다(#1000): 작업자는 `MEMORY.new.md` 끝에만 덧붙이고 `MEMORY.md`는 dream만 정리한다. 이관은 `lane_memory.migrate()`를 `fa init`이 부른다(레인 에이전트의 `memory: project`·옛 "Record durable…" 줄 교체, `.gitattributes` union을 MEMORY.new.md로). 역할 에이전트는 건드리지 않는다. `tests/test_lane_memory.py::test_this_repository_lane_agents_are_migrated`가 이 저장소 에이전트의 이관 상태를 지킨다. 수락 시험의 `_publish` 가짜는 `lambda *args`라 새 인자는 위치 인자로 넘겨야 한다.
- 꿈 PR은 올린 때가 아니라 병합된 때 완료다(#1000 재시도). 워커는 `dream-published` 사건만 남기고, tick의 `orch_dream.start()`가 PR이 닫혀 있으면 `list_prs("merged")`로 병합을 확인해 `dream-done`을 기록한다. union 병합은 충돌 없이도 꿈이 지운 대기 줄을 되살린다(빈 쪽+base의 추가). 그래서 `fa orch merge`는 merge-base 이후 base의 기억 파일이 바뀐 꿈 PR을 거절한다. conftest는 시험 속 `git commit/push/checkout`을 막으니 브랜치는 `git_history.update` + `update-ref`로 만든다.
- 꿈 PR 병합 확인은 Git 조상(merge-base)이 아니라 공개 때 `dream-published` 사건에 남긴 입력·출력 sha256 지문과 비교한다(#1000 2차 재시도). rebase가 merge-base를 새 base로 옮겨 조상 비교를 무력화한다. 레인 기억 폴더 이름은 `lane_memory.memory_dir()` 하나로만 정한다(agent 있으면 agent, 없으면 레인 이름). 에이전트 파일 정규식은 BOM·CRLF(`﻿?`, `\r?\n`)를 받아야 한다.
- `.gitattributes`의 대기 기억 union 줄은 `lane_memory.union_change()` 하나가 설치하고, init(새·재실행)과 `add_lane`이 모두 부른다(#1000 3차). init은 이관 대상 파일을 "아직 이관 필요"가 아니라 `git.uncommitted_paths(lane_memory.managed_paths())`로 찾아 커밋한다. 그래서 init·lanes·order 시험의 정확한 커밋 목록에 `.gitattributes`가 들어간다. 커밋 실패 재현은 `test_init.setup`의 `commit_fails`로 하되, 첫 init을 성공시키면 HEAD가 이미 이관된 상태라 재현이 안 된다.
- base를 작업자 브랜치에 합치는 단일 경로는 `GitRepo.merge_base`다(run_conflicts·run_publish_reviewed). 양쪽이 모두 바꾼 `MEMORY.new.md`는 union 결과를 버리고 `lane_memory.merge_pending`(base 버퍼 + 브랜치가 덧붙인 줄)으로 바꾼다(#1000 4차). `fa orch merge`는 GitHub에서 바로 합치므로 `pending_both_changed(checked.head, origin/base)`면 조정 병합을 PR 브랜치에 푸시하고 멈춘다. 시험에서 PR 브랜치가 원격에 없을 수 있으니 브랜치 대신 `checked.head` sha를 쓴다. 작성 규칙 안내는 에이전트 파일에 없으면 `run_lane_skills._writer_contract`가 붙인다.
