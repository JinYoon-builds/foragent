- `foragent/cuts.py`: `[cut: N more chars|lines; full text: <abs>]`, full copies in `<state>/runs/issue-N/` (`cuts.issue_dir`, `dir_for_log` maps `logs/issue-N.log`). Head cuts stop at a line end and put the notice right after, so the acceptance prefix-matcher counts exactly.
- `WholeFailure(str)` (run_attempt) marks failures whose parts are already limited (all failing checks, all review findings); `_implement` passes `failure_limit=None` for it like CIFailure. Raising it in `AttemptFailure` turns it into str; runner reads `exc.failure` to keep it whole.
- Parent context: `Approval.parent_context` (None = unread). `run_parent.parent_context()` freezes it lazily in `_prepare_implementation` via `tracker.parent_issue()` (one `/issues/N/parent` call returns the whole parent); the resume prompt restates it every time, only for bodies with `foragent:plan` marker; re-approval rewrites the snapshot without it.
- Moved files: `GitRepo.moved_by(target)` (-M -C name-status from merge-base) before both `merge_base` calls in run_conflicts, and `moved_between(previous, new target, paths)` (from their merge base) in `_prepare_target` target switches; `attempt.moved_files` is named once in the next prompt and logged via messages `moved_files_log`.
- Stop hook `check_done` reports every failing command; its 2000-char limit uses `cuts.tail` into the claude run dir (`stop-check-<i>.log`). `moved_between` uses `--find-copies-harder` so copies from unchanged files count. main split state.py: Approval lives in `state_records.py`, `save_approval` in `state_local.py`.
- conftest blocks `git commit/checkout` in tests: build history with hash-object/mktree/commit-tree/update-ref.
- Merge lesson (2026-10-26): a stalled-restart WIP commit can flatten an earlier main merge, so `git merge-base HEAD MERGE_HEAD` points at the old main and files the issue never touched conflict. Fix: `git diff <previous main> <WIP>` is exactly the issue's change; per conflicted file run `git merge-file -p <main> <previous main> <WIP>` (files outside that diff take main's copy). This leaves the index untouched. `.foragent/` is gone after a worktree recreate, so rewrite REBUTTAL/TRY.
- main's `run_previous.py` (previous-attempt summary) had the same silent cuts (stop text, `-n50` commits, files list, review tail); they now use `cuts.tail`/`cuts.head_lines`.
- `cuts.head` backs off to a line end only within `LINE_SLACK` (200) chars of the limit; an unbounded backoff kept 28 of 6000 chars for a long QUESTION.md line.
- Review round (2026-10-26): handoff state must survive limit-wait/restart. `Run.moved_files` and `Run.resume_whole` are carried by `start_run`; `_implement` clears moved_files only after a normal result. Parent text is written by `StateStore.freeze_parent_context()` (compare-and-set under `_state_lock`; save/clear_approval also lock). `_state_lock` is a non-reentrant flock: never call these while already holding it.
- Review round 2 (2026-10-26): `_implement` saves this turn's feedback (`resume_reason`+`resume_whole`) before calling the executor; `_available_executor` appends an executor error to it instead of replacing it. Native Claude gets `lane_memory_notice()` (Claude loads only 200 lines/25 KB of MEMORY.md) in fresh and resume prompts. `GitRepo._split_into()` finds split parts by added-line overlap (git -C needs whole-file similarity). `_verify_review_head` runs all commands and saves `runs/issue-N/review-head-checks.txt` for `orch.resolve`'s retry hint.
- Review round 3 (2026-10-26): one failure bundle `cuts.failures_path()` written by `run_checks.save_failures()` on every verification exit (timeouts too; cleared on pass); read only by `run_previous.saved_failures_section()` in `previous_attempt_summary()` and the resume prompt, so every retry path gets it. Main's review panel calls `build_review_prompt` too — pass `full_text_dir` at every call site.
- Review round 4 (2026-10-26): `run_previous.saved_feedback_section()` = latest review (whole, skipped when every finding line is already in the failure text) + failure bundle, for fresh and resume prompts. Verifiers are wrapped (`_verify_contents`, `_check_review_head`) so exceptions save gathered failures via `_keep_gathered()`; check_done's `report()` prints gathered failures plus the error. Tests that call verifiers directly under `run_case` must finish the run and drop `running` or teardown fails.
- Review round 5 (2026-10-27): `save_failures(..., complete=False)` updates only the commands that ran (per-command entries in `check-failures.json` beside the text bundle); only a full implementation verification replaces or clears the bundle. PR-head checks are always partial (Done when only).
- Review round 6 (2026-10-27): bundle entries are keyed per invocation (`<k-th run of the command>:<command>`), never by command text; `save_failures` returns this call's failed invocations, independent of saved entries. Re-verification saves the first pass before starting the second. `cuts.save_full` writes a temp file then `os.replace`.
- CI lesson (2026-10-27): unit tests call run_conflicts helpers with SimpleNamespace attempts lacking ctx.store; helpers must not touch the store when there is nothing to record. CI job logs: `gh api --allow-escape-sequences repos/<repo>/actions/jobs/<id>/logs` works while the run is still in progress.
- Review round 7 (2026-10-27): no folder is inferred from a log name. `cuts.read_tail(log, offset, limit, kind, directory)` takes the owner (`cuts.issue_dir`) and names copies `<log stem>-<kind>-<offset>.log`; `_check(..., full_text_dir=)` is passed by every issue-owned caller except check_done (locked acceptance fake takes 4 positional args; its log is already in runs/issue-N).
