- `update_check.py`: `check(config)` caches `<machine_root>/update-check.json` (checked_at, latest, installed) for 24h; failures cache latest=null. `update()` does a fresh lookup, `uv tool install git+...@<tag>` via `orch_reinstall._uv` under `<machine_root>/install.lock`, then restarts gates from `~/Library/LaunchAgents/dev.foragent.*.plist` with `Launchd(root).install()` inside plain `StateStore.tick_lock()`.
- Use `tick_lock()`, not `hold_tick_lock()`: the locked test re-probes the lock in the same thread, and hold_ reenters (yields True).
- `tests/conftest.py` autouse sets `FORAGENT_UPDATE_CHECK=off` so other brief/gate-status tests never call gh; the update test delenv's it.
- `fa update` treats the cache's `installed` tag as current (package metadata stays 0.1.0 across releases); it reinstalls only when a newer tag exists or `pending_restart` is non-empty (the locked busy-retry test expects a full reinstall then).
- `.foragent/acceptance-exclusions.json` is runner-generated by `ci_mode.stage_exclusions()` and lists the issue's own locked file by #327 design; a reviewer flagged it — answer with REBUTTAL, don't edit it.
- Pre-existing failures in test_star_prompt / test_cli_split / test_fa_briefing_scorecard (24) belong to other issues.
- Review fixes: `check()` holds a blocking `update-check.lock` around read→lookup→write (concurrent brief/status share one lookup). Busy/failed gates after a successful install go into the cache's `pending_restart`; the next `fa update` repeats the whole update. Boundary tests: `tests/test_update_check_unit.py`.
