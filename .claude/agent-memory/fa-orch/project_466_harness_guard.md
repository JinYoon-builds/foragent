- `harness_guard.changed_harness_paths(git, target_ref, files)` reuses `GitRepo.changed_paths` (index vs merge-base, `--no-renames`) so renames give both paths and target-only changes are excluded. pyproject compares `[tool.pytest]` + `[project.entry-points.pytest11]` via tomllib on `<mergebase>:path` vs `:path`.
- Hook point: start of `run_checks._verify_implementation` (after `_prepare_target`, before checks). Every head measurement (implementer turn, conflict resolution, base-move re-verify, CI retry) passes there. `run_publish._guard_harness` commits, `_push_branch`, `_open_or_update_pr`, then `flag()` + `needs-human` label and `raise ExecutorStopped("held")`; `run_issue` records the outcome. `_review_only` (used by `orch resolve` too) calls `_hold_harness_change` before `_verify_review_head`.
- **Why:** `flag()` only adds `blocked`; specs asking for needs-human need an explicit `add_labels`.
- **How to apply:** unit tests in this repo must use plumbing git (`write-tree`/`commit-tree`/`update-ref`); conftest asserts against commit/checkout/reset/push/stash. In zsh, `fa test $files` passes one argument — use `xargs`.
- Related: [[project_376_base_move]]
- Review round 2 lessons: run the guard (stage first) before EVERY `runner._check` on the head, inside the verify loop and in `_verify_review_head`, not once up front. A Done when command can generate harness files, and pass 2 would otherwise accept them. Read Git data as raw bytes (`subprocess` without `text=`), because `GitRepo._call` decodes with `errors="replace"`. An absent pyproject must normalize to the same value as a pytest-free one. APFS rejects non-UTF-8 file names, so such tests skip on macOS.
- Review round 3-4 lessons: guard every head measurement structurally. `run_checks._check` calls `harness_guard.before_measurement(worktree)`, and each run path registers a guard for its worktree (`guard_measurements`). Do not chase call sites one by one. Compare TOML values by type: `false == 0` and `nan != nan` in Python. Compare against the *current* `origin/<attempt.target_branch>`, not `attempt.start_ref`, which is pinned for policy and replay and lags after a merged-in target.
- Review rounds 5-6 lesson: never judge measured content from the runner's index (`stage_changes` drops `.foragent/` and local skills), and never rebuild an index either. A rebuilt index loses force-added ignored files. Read without writing: `diff --name-status -M <merge-base> HEAD`, `diff --cached --name-status -M HEAD`, and `status --porcelain=v2 -z -uall --ignored=matching` (matching keeps `.venv/` as one entry). For pyproject, compare the HEAD blob, the index blob and the disk bytes with the base.
- Review round 7 lesson: read every side of a file (disk, HEAD, merge base, index) through a typed reader. Anything that is not a regular file (directory, symlink to a directory, FIFO, tree, symlink or gitlink mode, conflict stage) counts as a change and must never raise. Open the disk file with `O_NONBLOCK` and check it with `fstat`, so a FIFO cannot block.
- Round 8-9 lesson: detection never needs staging, so run the guard before every `stage_changes` (in the hook, `_verify_contents`, `run_conflicts`, and the review guard and final step). Keep `_preserve_failed_implementation` raising, because the scheduler tests expect `wip-preservation-failed`. Catch its GitError only in `_implement_and_publish` `finally` when the outcome is `held`. Apply break-it to every fix: break it, see the named test fail, restore. Never type a bare `cat > /dev/null` into a command; it waits on stdin and hangs.
- Round 10-11 lesson: a hold must publish what the guard judged. `_guard_harness` runs `stage_changes(skip_refused=True)` before committing, and Git-refused paths are named in the comment. Run every test in the FOREGROUND, in chunks under 600 s (split by file). Never end a turn while a background test is pending; a woken session hung until the stall kill.
- Round 12 lesson: judge each harness candidate by its WORKTREE entry (lstat; symlink compares by link text) against the merge base. Do not judge by HEAD or the index: during a pending merge HEAD lacks the target side, so inherited files looked introduced. The worktree is what checks load and what the hold publishes. Unit tests may run a real `git merge --no-commit`; conftest bans only commit, push, reset, checkout and stash.
- Round 13 lesson: runner-side reads of worktree files (`_uses_local_only`, `_related_unit_tests`, `has_pull_request_ci`) must use `harness_guard.read_regular` (O_NONBLOCK + fstat S_ISREG), and the guard runs before them. Tests CANNOT kill a hung child: conftest blocks signals, so a `subprocess.run(timeout=...)` hangs on the kill. Make the child end itself with `signal.alarm(10)`. Run break-it steps one per command, with the restore step after `;`. A killed shell otherwise leaves the source broken; check the keep files.
- Round 14 lesson: harness change = Git mode + content, on every side (tree mode from ls-tree; disk mode from the execute bit, ignored when core.fileMode is false). pyproject still counts only its pytest tables. A break-it test can pass for the wrong reason: under core.fileMode false Git never lists a chmod-only path, so make the path a candidate another way.
- Round 15 lesson: never spawn git directly in guard code; go through the GitRepo object (`run_bytes`). The locked acceptance test `test_irreversible_paths.py` uses a duck-typed fake Git that forbids Popen, so start from `changed_paths()` and add raw views only if the object can run Git.
- Round 16 lesson: with core.fileMode false, the worktree side takes the mode Git will stage, not "unknown": the index stage-0 entry (or "ours" in a conflict), else HEAD, else 100644 for a new file. `git update-index --chmod=+x` is the recorded change that must still hold.
- Round 17 (fail-closed bar 10-29) lesson: harness paths stay raw bytes end to end. Files entries are UTF-8 encoded and matched as byte globs; a non-UTF-8 harness path, a symlink or submodule on either side, an unreadable blob, or an unparsable pyproject always holds. Guard Git calls use `-c core.precomposeUnicode=false` (macOS rewrites NFD to NFC) and `--no-renames` (-M reads blobs). The hold uses `flag(needs_human=True)`. Non-UTF-8 paths can be tested on APFS through index-only entries (`update-index -z --index-info`) and `mktree --missing`.
- Round 18 lesson: with core.symlinks false, the worktree hides a recorded 120000. Judge Git-recorded entries the worktree cannot show: index type (`ls-files -v -s`), index content of skip-worktree or assume-unchanged entries (tag != H), and HEAD type for runner-unstaged paths. Never normalize Files entries; split on "/" only.
- Round 19 lesson: a run_case test with two threads and the fake `ctx.sleep` spins `await_turn` 30 fake seconds per loop at CPU speed, so slower code can push the waiting run past its budget. Reproduce by holding the other run real seconds after merge, then pace the fake sleep with a short real pause (a bigger budget alone does not help). To compare against main, `git archive origin/main src` into the git dir and use PYTHONPATH.
- Round 20 lesson: anything that can recurse on PR-controlled input (TOML parse, canonicalization, == on nested tuples, glob matching per path component) must be iterative or caught. A failure while judging one candidate holds that path. Test each defense layer directly, or an outer catch hides the break.
