`SilenceWatchdog.observe()` is the one decision. Commands: `run_logged(watchdog=)` polls every 5s and sends stdout to a private file, so harness log writes are not counted as output. `_check` always passes one, so `timeout_s` is ignored. Runs: `scheduler_silence.py` keeps state in `<state>/silence/N.json`. Do not put it under `runs/`, because that folder parses `issue-N.json` names as integers.
**Why:** #431's fork test needs fresh listings for stops, and #435 needs exactly one listing for a silence stop. `processes.quiescent_tree()` limits snapshot reuse to trees proven silent.
**How to apply:** 고정 제한을 가정하던 단위 시험(test_scheduler, test_executor_recovery, runner_support의 run_case)은 `max_runtime_minutes=90`을 명시하고, scheduler 계열은 `silence_minutes=24*60`도 명시해 stall·runtime 경로를 그대로 시험한다. 인수 시험의 가짜 git에는 `at`이 없어 제품 코드에서 getattr로 우회했다(`_checkout`, `follow_base`). 감시기 판정 기록은 정지가 성공한 뒤에만 남긴다(거부된 정지는 stop-refused만 남는다). zsh에서는 `$files`가 낱말로 나뉘지 않으므로 `${(f)...}` 배열을 쓴다. 단위 시험 묶음이 10분을 넘으면 나눠 돌린다.

2차 리뷰(6건) 반영: 실행기의 예산 `_remaining`은 안전망에 10분 여유(`RUNNER_MARGIN_SECONDS`)를 더한 값이다. 그래서 게이트의 안전망 정지(WIP 보존, ready 복귀)가 먼저 일어난다. `max_runtime_minutes`는 scheduler와 `past_runtime_limit()`(단계 경계에서, 직전 검사나 리뷰가 멈췄을 때만)에서만 쓴다. fa doctor는 `RunContext.deadline_seconds`를 쓴다. 침묵 정지와 안전망 정지는 항상 stalled-restart이고 재시작 예산을 쓰지 않는다. CPU를 읽지 못하면 침묵으로 보지 않는다(`Decision.cpu_known`). 침묵한 트리를 멈출 때는 `read_children()`로 늦게 생긴 자식도 찾는다. 기준선 통과 ID는 pytest 플러그인 `RESULTS_PLUGIN`이 기록한다.

3차: 대기 루프(CI 폴링 `run_publish` 126/150, `ci_mode` 227, merge turn `run_merge_turn`)는 범위 밖이므로 `_wait_remaining()`으로 예전 한도(`max_runtime_minutes`)를 유지한다. 이 함수는 `runner._remaining` seam을 거쳐 부른다. transient 실행기 실패도 진행 없는 단계로 보고, 한도를 넘었으면 `past_runtime_limit`로 timeout 처리한다. `test_orch.py`는 merge turn 대기가 24시간이면 10분 넘게 돈다(멈춘 것처럼 보임). `faulthandler_timeout`을 걸고 백그라운드 `-v`로 실행하면 어느 시험인지 찾을 수 있다.

4차(main 병합): main(#433)이 timeout된 캡처도 `<key>.json`에 timed_out=True로 기록한다. `load_acceptance_baseline`이 그런 기록을 None으로 돌려야 잠긴 침묵 시험이 통과한다. dream 실행(run.key=`dream-<lane>`)은 같은 정지 경로를 지나므로 error로 끝나고 라벨을 건드리지 않는다. 출력 로그는 `orch_dream.log_path`이고, `_kill_run`에 `decided=run`을 넘긴다. 크기 제한 때문에 run_baseline(600), run_checks(600), scheduler_recovery(300)를 줄였다. 플러그인과 재개 코드는 `run_baseline_plugins.py`로, 감시기 입력은 `watchdog.silence_args(ctx)`로 옮겼다. main 기준선 비교 방법: 작업공간 안 `.foragent/base`에 `git archive <main> src tests pyproject.toml`을 풀고 그 안에서 `PYTHONPATH=src ../../.venv/bin/python -m pytest`를 실행한다 (내 conftest의 read_children 패치를 피한다).

5차: 실행을 끝내는 검사(관련 단위 시험, PR head의 Done when, 기준선 캡처와 ID 수집)가 감시기로 멈추면 `run_waits.watchdog_restart`가 stalled-restart로 끝내고 ready로 돌린다(기준선은 `SilentCapture`). Done when, CI, local-only 검사는 실패 결과로 넘긴다. Stop hook은 `--history-root`/`--safety-net-seconds`를 받으며, gate는 값이 있을 때만 넘긴다(잠긴 cli_split의 3인수 가짜). 대기 루프는 max_runtime이 없으면 90분(`WAIT_DEFAULT_MINUTES`)이다. 감시기 판정 기록은 `_kill_run(on_stopped=...)`로 프로세스가 멈춘 직후 남긴다. 잠긴 `test_baseline_prebuild.py:257`이 `max_runtime_minutes * 60`을 계산하므로 기본값 None과 충돌해 QUESTION.md에 남겼다. main에서 이미 실패하는 시험: dream_view 6개, harness_guard 10개, baseline_prebuild의 main_move 1개.

6차(오케스트레이터 정정): `max_runtime_minutes`의 기본값은 90으로 유지한다. None 가드는 모두 제거했다. 실행기 세션의 `timeout_s`는 `_runtime_left`(main과 같은 값)이다. 대신 `run_logged(quiet_timeout=True)`가 한도에 닿아도 바로 끊지 않고 그때부터 `_past_budget()` 감시기로 60초 동안 증가가 없을 때만 멈춘다(`RUNTIME_QUIET_SECONDS`). 단계 경계의 `_remaining`은 안전망+10분이다. 잠긴 `test_related_tests_record.py`가 관련 시험 시간 초과를 'timeout'으로 기대해서, 리뷰가 요구한 stalled-restart와 충돌한다. QUESTION.md에 남겼다. main에서 이미 실패하는 시험: test_test_slots 5개 추가.

7차(main 병합, run_publish 분할): `_remaining`은 main과 같은 뜻(max_runtime 예산)으로 되돌렸다. 실행기 timeout_s, 검사의 기록용 limit, 대기 루프에서 쓰며 시험은 이 seam을 바꿔 끼운다. 단계 경계의 `<= 0` 검사는 새 `_budget_left`(안전망+10분)를 쓴다. 잠긴 test_related_tests_record는 관련 시험의 timeout_s가 main 값과 같기를 요구하고, 결과는 이제 stalled-restart를 기대한다. CI 대기 루프는 `run_publish_ci.py`로, `_check_publication`은 `run_publish_merge.py`로 옮겨졌다.

8차: 재개 캡처의 `--deselect`는 접두어로 일치한다. 그래서 RESULTS_PLUGIN이 수집 전체(`pytest_deselected` 포함)를 `.partial`에 남기고, `deselectable()`은 다른 ID의 접두어가 아닌 것만 제외한다. 첫 표본은 마지막으로 측정된 활동이 60초 안이면 `grew`로 본다. 로그 파일 시각은 다른 시계라서 쓰지 않는다(가짜 시계 시험이 깨졌다). `_watch`는 stderr 채널(`channels=`)도 출력으로 센다. `CheckResult.stop`이 감시기 판정을 담고, `run_waits.after_check`는 안전망 정지면 재시작한다(Done when, 기준선 검증, CI-mode, local-only). silence 정지 트리 탐색은 tick 스냅샷의 자식만 쓴다. `read_children`과 conftest 가짜는 지웠다(macOS psutil children()이 전체 표를 읽는다). test_scheduler와 test_orch_dream_unit의 '진행 중인데 한도 초과로 kill' 시험은 진행이 20분 전인 경우로 바꿨다.

9차(재설계 r40): main을 기준으로 다시 만들었다. `watchdog.decide(Facts)`가 유일한 판정, `outcome_for(kind)`가 유일한 결과 매핑이다 (safety-net > runtime-limit > silent, runtime-limit도 같은 침묵이 필요하다). 첫 표본은 시작 시각 기준이고 증가는 0이다. CPU 필드가 없는 행 형식은 증가 0, cpu_time=None(읽기 실패)은 unknown이다. 표본은 `Run.silence`(compare=False)에 저장한다. 사실 행은 실행 로그에 남긴다. 멈춘 검사는 `run_waits.after_check` → `end_by_watchdog`로 끝난다(재시작 횟수에 더한다). 한도의 유예는 `watchdog.runtime_limit_seconds`(+10분) 한 곳에만 둔다. 꿈 실행은 main의 한도를 유지한다. 크기 제한 때문에 `run_baseline_resume.py`와 `scheduler_silence.py`를 따로 둔다. ci_mode, ci_local, run_execution, executors, runner*는 main 그대로다.

10차: `silence_minutes`의 기본은 None(미설정, 실제 창 10분)이다. `watchdog.silence_window`가 'config'와 'default'를 가른다. 멈춘 검사의 종류는 `stopped_check_kind(stop, run_elapsed, config)`로 실행의 안전망과 한도에 맞춰 다시 판정한다. `scheduler_silence.observe`는 판정에 쓴 기록에 표본만 바꿔(replace) 돌려준다. 그 사이 진행이 기록되면 `_kill_run`의 DECISION_FIELDS가 막는다. 기준선 캡처는 RESULTS_PLUGIN을 다시 쓴다. 통과는 끝나는 즉시 기록하고, `--deselect` 접두어로만 빠진 시험은 hookwrapper가 되돌린다(정확히 남긴 ID만 제외, 그 수를 기록). PR head의 Done when은 경과 시간만으로 멈추지 않는다. 비교 기준선은 HEAD~1이 아니라 main 커밋(a7433000)이다. 브랜치 커밋이 병합 커밋이다.

11차: 플러그인이 정확히 남긴 ID를 모두 직접 제외한다(--deselect에 넘기지 않은 접두어 ID 포함). 제외 수는 `len(original) - len(items)`, 즉 실제로 돌리지 않은 수다. `resume.combine`은 다시 돌린 ID에 이번 결과를 쓴다. 선택과 개수는 같은 한 곳(플러그인의 최종 items)에서 나와야 한다.
