- `fa orch facts` lives in `orch_facts.py`; CLI wiring is in `commands/orch.py` (`INBOX_ACTIONS` includes "facts", so no Git/GhTracker setup). Acceptance tests snapshot every file under tmp_path (bytes + mtime), forbid Popen/kill and guard `open(plan.json)`.
- `capacity.machine_load()` writes a sensor file and lock under `machine_root()` (tmp_path in tests). Facts wraps it in `capacity.observing()` (ContextVar) so the real sensor is read-only, while a test's patched `machine_load` is still called.
- Do not use `capacity.machine_runs` in read-only views: it probes sibling runs with `os.kill(pid, 0)`.
- Related unit checks pass `--junitxml <path>` (space form). Locked `test_fast_checks` counts `--junitxml=` commands as the single baseline discovery. Report path `<state>/runs/issue-N-related.xml` is unlinked before and after each check so a timeout never reuses old timings.
- `_check(..., clock=ctx.monotonic)` measures only the command inside the test slot (`CheckResult.seconds`).
- Phase events (`kind: phase` in orch-events.jsonl) are assigned to the latest execution of the issue started at or before the event `at`. Waste = phases ending in `-wait` plus events with `repeat_of`, each counted once.
- Test-slot `current` = shared `test-slots.json` capped by config `test_slots` (the locked test demands 4 with no machine.yml). What the runner really admits is `capacity.effective_test_slots()` (machine.yml default 2 applies), reported as `resources.test_slots.admitted`.
- Review lesson: facts must replay the gate's own admission, not re-derive it. `overlap_files.admits()` (split from `can_start`) and `claims(measured=False)` give the read-only file rule. `scheduler_start._lane_held` gives quota holds. The machine cap (capacity.json, capped by machine.yml) is compared with machine-wide runs; the project's `max_parallel` only with this project's runs. Locked keys: `test_slots` must be exactly current/queue_length/total_wait_seconds, so extra fields like `admitted` go under `resources`.
- Merges since tidy: `fa tidy done` → `tidy.status()` count; a tidy-done event → `merge_times()` first, then `finished_at`.
- Review round 2: a consumer that passes on seeded fixtures is not enough. Reviewers check that production code emits what facts reads. Phase events are now written by `StateStore.update_run` (on phase change) and `finish_run` (#224 schema, under the state lock). `_test_slot` sets `test-slot-wait`; baseline capture sets `baseline`/`baseline-wait`; `Run.phase_work_id` + `work_events` (carried by start_run) produce `event_id`/`work_id`/`repeat_of`. `orch.log` skips kind=phase.
- Replay parity: lanes via `issue_lane(labels, config.lanes)`, order via `orch_queue.ordered`, union via the gate's recorded `union-merge-paths.json` (`overlap_files.record_union`). An empty repo root makes `_filesystem_case_sensitive` return None, so every pattern overlaps; give unit-test roots a file.
- Review round 3 (orchestrator hint, 3 classes): (1) facts reads many files that writers change in steps (journal first, then run record). `collect` compares a version stamp (mtime/size/inode) before and after and recomputes; read current runs once and pass the list. (2) Work identity = `phase_work_id` + `phase_work_started_at`. A phase change clears it unless passed; nested waits restore it with `run_waits.phase_identity`/`restore_phase` (slot, baseline lock, overlap, CI capture). (3) Every shown fact needs a production writer: `record_usage` appends a bounded `usage-history.jsonl`, and `tidy.done` journals `tidy-done`.
- Review round 4: one repeat rule for open and closed work (`state_runs.work_event`); work named with its phase must record `phase_work_started_at` at once, or restored segments look like repeats. The facts version stamp must cover every input, including sibling stores' runs/run-starts, machine.yml and memory-sample.json. Gate parity: only `critical` memory holds starts (#497), overload (≥ OVERLOAD_LOAD) shrinks budgets, and outside `run_hours` the tick starts nothing.
- Review round 5: facts must use the gate's committed config (`scheduler_config.record_tick_config`/`tick_config`, `tick-config.json`); read recorded holds (`github-pause.json`) and in-flight blockers (running `overlap-wait`); treat a running record that already has a history entry as finished (`_still_running`); dedupe phase closes by `(issue, phase, phase_started_at)`.
- Round 6 (orchestrator design decision): no more per-input patches. `collect` takes shared flocks on existing lock files (all repo `state.lock` sorted → `capacity.lock` → sensor lock), copies every input once into a temp snapshot (never plan.json), reads machine files and the sensor once, and computes only from that. Shared locks on existing files keep the state dir byte-identical (the locked test compares files); creating lock files would break it. `tidy.done` uses one timestamp for tidy.json and its event; `_observed_load` honours FORAGENT_CPU_BUSY=off.
- Round 7: rediscover stores after taking the locks (reservations create sibling stores under `capacity.lock`) and before release; pass only the checkout config to `collect` (it applies `tick_config` on the frozen snapshot); GitHub wait and run_hours skip the whole start loop before cap/quota/files, while critical memory stops the loop at the first issue that passes every check.
- Round 8: config files are inputs too — copy the global config and the checkout `.foragent.yml` inside the locks and load from the copies (`collect(..., checkout=True)`, `tick_config(..., global_path)`); take `now` and sibling process probes inside the locks.
- Round 9: every credited wait goes through `run_waits.WaitPhase` (executor backoff `executor-wait`, `_credited_wait(..., phase)` for overlap/baseline/merge lock, test-slot queue), so waste comes from phase events only. The merge lock opens its phase lazily (`eager=False`), so an immediate acquisition adds no events; the #224 scorecard test expects exactly five phase events.
- Round 10: don't re-implement gate ordering — main moved to one global ranked loop (`scheduler_start._ranked`), so facts now calls `_ranked(ctx, ready, claims=...)` and mirrors `_start_ready` step by step. Sensor: `capacity._busy_now` is the shared busy rule; the read-only `_observed_load` must use it, never the bare saved `cpu_busy`.
- Round 11: every path that runs tests must be instrumented, not just `_verify_implementation`: `run_checks.run_related_check` (records related checks; used by `ci_mode.review_checks` too) and `run_waits.in_phase(n, ctx, "checking")` for `_verify_review_head`, `review_checks` and `ci_local.fallback_comparison`.
- Locked split tests cap new modules: `test_cli_split` 300 lines for every non-base module (incl. commands/*), runner/run_publish splits 600, state split 300. Facts is split into orch_facts / orch_facts_runs / orch_facts_resources, and the phase journal lives in state_phases.py. run_publish.py is 842 on base (pre-existing failure); never add lines to it.
