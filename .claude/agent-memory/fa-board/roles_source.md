`foragent/roles.py` owns `roles:` (#769). `edit_roles` rewrites only the top-level roles block as block YAML at its position (appended when absent); bytes outside stay identical, comments inside are dropped with one stderr notice. Bar set by Jin 2026-10-27 after reviews kept finding comment loss in line-level editing — do not go back to field-level edits. init appends roles via `_add_config` when the key is missing, and uses `edit_roles` when roles exist but defaults are missing (`_config_text`).

- **Why:** every init now writes roles with `created_at`, so exact-text tests in `tests/test_init.py` compare `without_roles(...)`/`config_values(...)` and `added_keys` ends with `"roles"`.
- **How to apply:** once this repo's `.foragent.yml` gains a new config key, the globally installed `fa` (older) fails with "unknown configuration key". Run `uv run fa test ...` from the worktree instead of `fa test`.
- Role commands run real git in the acceptance fixture whose origin is a local path, so `remote_slug()` fails; the event store then uses `"local" + root path` as key (skipping the event was blocked in review). Default role agents created by init take skills from the roles entry (`role_agents.missing_files(root, skills)`), never the template. Skills resolve also from an installed `.claude/skills/<name>/` copy.
- Role verbs commit only paths whose bytes changed (`_Edit.snapshot`/`publish`) and always append the orch event; `git status` (`uncommitted_paths`) inside `fa role` trips the locked init fixture's no-sleep/kill guard, so do not call it there. An existing agent file keeps its body even when empty; only a missing file gets the generated body (#769 review).
- Every role verb derives all three projections: entry, agent file and memory (`_ensure_memory`, created only when missing). `role_drift` reports a missing agent or MEMORY.md so `fa role set <name>` is the repair path (#769 review: set skipped memory).
- Publication (#769 round 4): `_Edit.publish(owned)` runs `ls-files` + `git add -A -f -- <owned that exist or are tracked>` + `diff --cached HEAD`, then commits exactly the differing files. Owned = .foragent.yml, agent file, memory directory (not just MEMORY.md). Never commit only "files this command wrote" — hand deletions must be published too.
- Tests cannot run real `git commit` (conftest `no_forbidden_git_commands`). Use `commit-tree` + `update-ref` plumbing, e.g. `recording_commit(commits)` in tests/test_init.py, so HEAD advances between role commands.
- A `git rm` deletion exists only in HEAD (not worktree, not index): `git add` rejects such a pathspec, so `publish` stages only worktree/index paths but diffs ALL owned paths against HEAD; `commit --only -- <HEAD-only file>` commits the deletion (#769 round 5).
- Flaky SIGKILL/"must not sleep" in locked init fixtures: `subprocess.run(timeout=...)` polls with `time.sleep` when the child is not reaped at once, and kills it on the fixture's failure. Role commands use `roles._local_git` (no timeout, local-only git) as GitRepo runner; measure flakiness with 6–10 repeated runs before and after.
- init never routes roles through `_add_config` (it rstrips trailing blank lines and full-rewrites flow/closed/indented files). `_config_text` reads bytes (text mode turns CRLF into LF), applies `roles.edit_roles` (keeps the file's newline), and writes bytes. A file the block cannot be appended to (flow style) gets a warning and stays unchanged (#769 round 7).
- Never swallow a roles-source write failure: init raises ConfigError before writing anything (agents derive from the source). A `...` document end gets the roles block inserted before it. Default role skill copies follow the entry's skills (`role_agents._skill_dir`: repo `skills/<name>` first, then shipped), never the role's own name (#769 round 8).
- Round 9 classes: (1) skill copies are bytes (`role_agents._templates` values may be bytes; init writes with "xb"; `setup_paths` compares bytes) — PNGs and CRLF survive. (2) `roles._split_agent` reads bytes and returns (header, body bytes, line end); `fa role set` writes new frontmatter + the exact body bytes. (3) `edit_roles` is pure; the notice comes only from the writer (`report_dropped_comments` in `_Edit.save` and at init's config write), never from preparation that may run twice (init's board path).
- Locked `test_irreversible_paths::test_init_asks_nothing_and_defers_registration_until_a_touching_merge` requires re-init to leave an existing .foragent.yml byte-identical. So init writes roles only on fresh init or when a `roles` key already exists; `_Edit` (roles_commands.py) starts from `with_defaults` so the first `fa role` command writes the block. `test_cli_split` caps every src/foragent/*.py at 300 lines — roles code is split into roles.py (source, editor, drift) + roles_commands.py (verbs), re-exported from roles (#769 round 11).
- When a role verb inserts missing default entries into a legacy config, `_Edit.save` also derives their agent, memory and skill copies (`derive_inserted`) and `publish` commits them — every declared role gets its projection in the same command (#769 round 12). Whether re-init migrates a config with no `roles` key conflicts with locked test_irreversible_paths:346; asked in .foragent/QUESTION.md (recommend: always migrate, narrow that test).
